# 신규 상장 비용 측정기 — 설계

작성 2026-08-13 · 상태: 승인됨

## 왜 만드는가

2026-08-12에 크립토 전략 17개 계열을 검정해 전부 기각했다. 그중 다섯은 순전히
거래 비용 때문이었고, 신규 상장 숏이 그 하나다.

신규 상장의 **방향은 이미 측정됐다**. 폐지 종목을 포함한 716종목에서 상장 후 60일
중앙 수익 −26.59%, 양수 종목 29.5%, p=1.1e-28. 세 시대(2020~2022 / 2023~2024 /
2025~2026) 모두에서 부호검정을 통과했다.

죽은 것은 신호가 아니라 **비용**이다. 상장 7일차 진입 시 Corwin-Schultz 추정 스프레드가
28.9bp였고 왕복 66.4bp가 되어, 워크포워드 수익이 연 1.8%로 노이즈 수준이 됐다.

그런데 **상장 직후 구간의 스프레드는 한 번도 실측한 적이 없다.** 소켓 수집은
2026-08-09부터이고 기존 58종목은 전부 오래된 심볼이다. 이 구간은 거래량이 폭증하므로
7일차와 다를 수 있다.

이 물건은 그 하나를 잰다.

## 무엇을 하는가

바이낸스 `exchangeInfo`를 60초 주기로 감시해 신규 크립토 무기한을 포착하고, 거래 가능해지는 즉시
bookTicker·trade·depth20을 실측 기록한다. **주문은 넣지 않는다.**

답하려는 질문: **상장 직후 진입 창의 실제 스프레드는 몇 bp이고, 그 가격에 물량이 있는가.**

### 명시적으로 하지 않는 것

- 주문·포지션·손익 계산 — 비용 가정이 검증되기 전엔 무의미하다
- 방향 예측 — 이미 측정됐다. 다시 재지 않는다
- 과거 상장 이벤트 재백테스트 — 2026-08-12에 이 데이터에서 나온 t값이 독립 표본에서
  **세 번 뒤집혔다**(리버설 3.33→−0.33, 매크로 3.32→−0.46, 잔차 8.83→−1.46).
  같은 함정을 만들지 않는다

## 구성요소

```
① 상장 감시기      exchangeInfo 60초 폴링 → 신규 크립토 무기한 등장·TRADING 전환 포착
② 소켓 기록기      bookTicker + trade + depth20@500ms 구독, 7일 기록
③ 비용 분석기      경과시간별 스프레드·깊이·거래량 프로파일 산출
```

### 데이터 흐름

```
exchangeInfo ──60초──▶ 처음 보는 심볼?
                          │ 예
                          ▼
              underlyingType == "COIN"
              contractType  == "PERPETUAL"
              quoteAsset    == "USDT"
                          │ 전부 참
                          ▼
                  status == TRADING?
                    │ 아직 아니면 계속 폴링 (최대 48h)
                    │ 예
                    ▼
        별도 프로세스로 소켓 구독 (기존 수집기와 분리)
                          │
                          ▼
     data/socket/<stream>/<심볼>/<YYYY-MM-DD-HH>.jsonl.gz
                          │
                          ▼
              비용 분석기 → 경과시간별 스프레드 표
```

### 설계 판단

**기존 수집기를 재사용하지 않는다.** `scripts/collect_book_data.py`는 2026-08-10부터
무중단 가동 중이며 58종목을 쌓고 있다. 심볼을 추가하려면 재시작해야 하고 그러면 그
기록이 끊긴다. 이벤트 심볼은 **별도 프로세스**로 띄우고 저장 레이아웃만 공유한다.
같은 레이아웃이므로 기존 분석 코드가 그대로 동작한다.

**공지 API를 쓰지 않는다 — `exchangeInfo`가 권위 있는 답을 준다.** 초안은 공지
제목을 정규식으로 파싱했으나 2026-08-13 실측에서 그 방식이 **조용히 틀리는 것**을
확인했다:

- `GIGADEVUSDT`를 크립토로 분류했지만 거래소 기준은 `HK_EQUITY`다
- 제목에 TradFi 표시가 없는 주식·원자재 상장이 다수다 (`AMDUSDT`, `NATGASUSDT`, `XPTUSDT`)
- 복수 심볼 공지 16건이 통째로 누락됐다 (`ZESTUSDT and BTWUSDT` 등)
- 목록 API는 시각 필드가 전부 `null`이다 (`publishDate`·`releaseDate`)

`exchangeInfo`는 같은 정보를 거래소 자신의 분류로 준다 — `underlyingType`
(`COIN`/`EQUITY`/`HK_EQUITY`/`KR_EQUITY`/`COMMODITY`/`INDEX`/`PREMARKET`),
`contractType`(`PERPETUAL` vs `TRADIFI_PERPETUAL`), `onboardDate`, 그리고 상장 전
`PENDING_TRADING` 상태까지. 제목 형식이 바뀌어도 흔들리지 않는다.

공지가 주는 유일한 이점은 리드타임인데, **기록은 상장 시점부터** 시작하므로 쓰이지
않는다. 그래서 뺀다. (공지~상장 사이 선진입 전략을 나중에 보게 되면 그때 되살린다.)

**기록 시작은 상장 시점이다.** 알고 싶은 것은 거래 가능해진 뒤의 스프레드이고,
그 전에는 구독할 스트림 자체가 없다.

**최우선 호가만으로는 부족하다 — `depth20`을 함께 받는다.** `bookTicker`는 최우선
호가만 주므로 "스프레드 1bp인데 그 가격에 100달러어치뿐"인 상황을 구분하지 못한다.
신규 상장 초기는 호가가 얇으므로 이 구분이 결정적이다. `<심볼>@depth20@500ms`로 상위
20호가를 함께 기록하면 스프레드와 체결 가능 물량을 동시에 잰다. 지금 계좌
(포지션 12~24달러)에는 최우선 호가로 충분할 가능성이 크지만, 나중에 규모를 키울 때
"얼마까지 가능한가"를 되돌아가 재지 않으려면 지금 받아둬야 한다.

**갱신 주기는 `@500ms`다 — 기본값(250ms)도 `@100ms`도 아니다.** 판정은 시간대별
스프레드 중앙값이므로 초당 2표본(하루 172,800개)이면 차고 넘친다. 호가 수준을 재는
것이지 체결 타이밍을 재는 게 아니므로 해상도가 필요 없다. `trade` 스트림은 그대로
전량 받으므로 체결은 누락되지 않는다.

실측(DOGEUSDT, 2026-08-13):

| 스트림 | 수신율 | 추정 용량 |
|---|---|---|
| `@depth20` (기본 250ms) | 3.73건/s | 58MB/일/심볼 |
| **`@depth20@500ms`** | **1.97건/s** | **31MB/일/심볼** |
| `@depth20@100ms` | 8.33건/s | 130MB/일/심볼 |

`@500ms`로 7일 기록 시 이벤트당 약 220MB다.

**스트림 가용성은 실측 확인됐다.** 이 환경은 `aggTrade`·`kline_1m`·`forceOrder`가
네트워크 레벨에서 차단돼 0건이 오는 것으로 알려져 있어(수집기 독스트링), `depth`
계열도 막혔을 가능성이 있었다. 2026-08-13 실측 결과 `@depth20`·`@depth20@500ms`·
`@depth20@100ms`·`@depth5`·`@depth` 전부 정상이며 20호가가 완전히 채워져 온다.

**기록 기간은 7일이다.** 판정에 필요한 창은 상장 후 1~24시간뿐이지만, 25~50bp가
나와 "보유기간을 늘려 재검토"로 가면 그때 필요한 것이 며칠 뒤의 스프레드다. 그
경우에 이벤트를 다시 기다리지 않으려면 지금 받아둬야 한다. 60일 전체를 받지 않는
이유는 그 구간 비용은 이미 기존 58종목 실측으로 대신할 수 있기 때문이다
(상장 초기가 아닌 정상 심볼의 스프레드는 이미 갖고 있다).

## 대상 필터

세 조건을 **전부** 만족하는 심볼만 기록한다:

```
underlyingType == "COIN"        # EQUITY/HK_EQUITY/KR_EQUITY/COMMODITY/INDEX/PREMARKET 제외
contractType   == "PERPETUAL"   # TRADIFI_PERPETUAL 제외
quoteAsset     == "USDT"        # USDC·USD1 등 제외
```

2026-08-13 exchangeInfo 859심볼 실측 분포:

| `underlyingType` | 심볼 수 |
|---|---|
| **COIN** | **699** |
| EQUITY | 133 |
| HK_EQUITY | 11 |
| COMMODITY | 8 |
| INDEX | 3 |
| KR_EQUITY | 3 |
| PREMARKET | 2 |

**주식·원자재 제외가 중요하다.** 기준이 된 −26.59% 측정은 크립토 신규 토큰
기준이다. 실제 주식을 추종하는 상품은 그 분포를 따를 이유가 없고, 섞으면 측정이
오염된다. 제목 파싱으로는 이 구분을 신뢰할 수 없다(위 「설계 판단」 참조).

### 이벤트 빈도 — 측정됨, 그리고 이것이 이 전략의 상한이다

`onboardDate` 기준 크립토 USDT 무기한 신규 상장:

```
2025-07  19    2025-11  14    2026-03   8    2026-07   3
2025-08  18    2025-12  14    2026-04   5    2026-08   1
2025-09  31    2026-01  15    2026-05   4
2025-10  29    2026-02   5    2026-06   7
```

**최근 90일 14건 = 주당 1.09건.** 2025년 가을 대비 한 자릿수로 급감했다.

두 가지를 뜻한다:

1. 판정에 필요한 3건은 약 3주면 모인다 — 6주 종료 조건 안에 들어온다
2. **이 전략만으로는 월 20% 목표를 채울 수 없다.** 주 1건이면 월 4~5거래다.
   비용 판정을 통과하더라도 포트폴리오의 한 축일 뿐이며, 이 사실은 판정 전에
   기록해 둔다 — 나중에 결과를 보고 기대를 조정하지 않기 위해서다.

| 상황 | 처리 |
|---|---|
| 첫 실행 | 기존 859심볼 전부를 "이미 본 것"으로 등록하고 시작한다. 안 그러면 첫 폴링에서 전 종목을 신규로 오인해 700개를 구독한다 |
| 재시작 | 본 심볼 집합을 파일에 유지해 중복 기록 방지 |
| 소켓 끊김 | 기존 수집기의 재접속 패턴을 따른다(지수 백오프, 23h 예방적 재연결) |
| `PENDING_TRADING` | TRADING 될 때까지 계속 폴링, 48시간 후 포기하고 로그에 남긴다 |
| 디스크 | 이벤트당 5GB 상한, 초과 시 기록 중단하고 로그에 남긴다. 실측 기준 이벤트당 약 220MB(depth20@500ms 7일) + bookTicker·trade 분이므로 상한은 폭주 방어용이다. 현재 여유 380GB |
| 알 수 없는 `underlyingType` | 거래소가 새 분류를 추가할 수 있다. **조용히 제외하지 않고 로그에 남긴다** — 그것으로 분류 체계 변경을 감지한다 |

## 판정 기준 (사전 등록 — 결과를 보고 조정하지 않는다)

2026-08-12에 과거 리포트에서 합격 기준이 사후에 하향된 사례를 발견했고
(`202603/..._r59_oos_validation.md`: OOS/IS 0.85→0.50, WR 42%→40%),
같은 날 나 자신도 두 번 그 함정에 빠졌다. 그래서 데이터가 오기 전에 못 박는다.

진입 창(상장 후 1시간~24시간)의 **실효 스프레드 중앙값**(24달러 체결 기준, 편도) 기준:

| 실측값 | 판정 |
|---|---|
| ≤ 25bp | 전략 진행 — 거래 로직 설계 착수 |
| 25~50bp | 보유기간을 늘려 재검토 |
| > 50bp | **2026-08-12 판정 유지, 프로젝트 종료** |

임계 근거: 어제 실측한 손익분기 왕복 100bp에서 역산(스프레드 편도 약 46bp + 수수료 8.6bp).

**판정에 쓰는 스프레드는 최우선 호가 스프레드가 아니라 `실효 스프레드`다.**
`depth20` 호가를 걸어 목표 포지션(24달러)을 실제로 체결시켜 보고, 체결 가중 평균가와
중간가의 괴리를 편도 비용으로 잡아 왕복으로 환산한다. 최우선 호가에서 다 채워지면
이 값은 최우선 호가 스프레드와 같아지고, 얇으면 그보다 커진다. 즉 **깊이 부족은
자동으로 더 나쁜 스프레드로 나타나며 별도 조건이 필요 없다.**

20호가를 다 먹어도 24달러가 안 채워지는 구간은 **체결 불가**로 기록하고, 진입 창에서
그 비율이 10%를 넘으면 스프레드 값과 무관하게 **종료**한다.

**판정 시점**: 크립토 신규 상장 **3건** 기록 후.
실측 주당 1.09건이므로 약 3주 예상.

## 테스트

이벤트를 기다리지 않고 전 경로를 검증한다.

| 대상 | 방법 |
|---|---|
| 대상 필터 | 실제 exchangeInfo 859심볼을 고정 자산으로 저장. `COIN`+`PERPETUAL`+`USDT` 699건 통과, EQUITY 133·HK_EQUITY 11·COMMODITY 8·INDEX 3·KR_EQUITY 3·PREMARKET 2 차단 검증 |
| 중복 방지 | 같은 심볼 두 번 투입 시 한 번만 기록 |
| 첫 실행 폭주 방지 | 빈 상태로 시작 시 기존 심볼 전부가 신규로 잡히지 않는지 검증 |
| 상장 대기 | `PENDING_TRADING` → `TRADING` 전환을 고정 자산 두 벌로 감지 |
| 소켓 기록 | **이미 상장된 심볼**로 세 스트림(bookTicker·trade·depth20) 30초 실구독 → 경로·형식 검증 |
| 스프레드 산출 | `data/socket/` 기존 58종목 실데이터로 시간대별 스프레드 표 산출 |
| 실효 스프레드 | 기존 데이터에는 `depth20`이 없다. 위 30초 실구독에서 받은 실호가로 24달러 체결을 걸어 검증하고, 최우선 호가에서 다 채워지는 경우 값이 최우선 호가 스프레드와 일치하는지 확인한다 |

실데이터만 쓰므로 실제 상장 없이도 전 경로가 검증된다.
프로젝트 규칙(테스트-코드 패리티)대로 pytest로 붙인다.

**주의**: 기존 58종목 실데이터는 `depth20`을 담고 있지 않다(수집기가 최우선 호가만
받는다). 따라서 실효 스프레드 로직은 과거 데이터로 회귀 고정할 수 없고, 실구독
표본으로만 검증된다. 이 한계를 알고 간다.

## 운영

```
상장 감시기   tmux 세션 'listing' 상시 (exchangeInfo 60초 폴링)
             기존 'collector' 세션은 건드리지 않는다
기록기       감시기가 상장 감지 시 자식 프로세스로 기동, 7일 후 자동 종료
분석         수동 — 3건 모이면 실행해 판정
```

감시 비용은 사실상 0이다. 60초에 `fapi/v1/exchangeInfo` 한 번(가중치 1, 공개
엔드포인트라 계정 레이트리밋 무관), 이벤트가 없으면 아무 일도 하지 않는다.

## 종료 조건

- 크립토 상장 3건 기록 → 판정 → **50bp 초과면 프로젝트 종료.** 더 파지 않는다
- 진입 창 체결 불가 비율 10% 초과 → 스프레드와 무관하게 **종료**
- 6주 안에 3건이 안 모이면 → 실측 주당 1.09건보다도 느려진 것이므로 거래 빈도
  관점에서 재검토 (이미 이 전략만으로 월 20%가 불가능함은 기록해 뒀다)
- 25bp 이하면 → **그때 비로소** 거래 로직을 설계한다
