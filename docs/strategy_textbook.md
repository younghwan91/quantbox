## 1. 시스템 한눈에 보기

QuantBox는 바이낸스 USDT-M 선물에서 **변동성이 극도로 줄어든 순간**(스퀴즈)을 포착해, 곧 터질 방향성 있는 큰 움직임에 올라타는 시스템이다.

두 개의 독립된 전략(축)이 하나의 슬롯 풀(10개)을 공유한다:

```
┌──────────────────────────────────────────────────────┐
│               QuantBox v14.1.0                        │
│          Dual-Axis Squeeze System                     │
├─────────────────────┬────────────────────────────────┤
│  Axis 1: VR Squeeze │  Axis 2: MA Cluster Squeeze    │
│                     │                                 │
│  "스프링이 눌렸다"   │  "모든 이평선이 한 곳에 모였다"  │
│                     │                                 │
│  ATR(8)/ATR(56)     │  SMA 20/50/100/200 수렴        │
│  < 0.50이면 진입    │  3% 이내 + 8봉 지속이면 진입    │
│  15m / 1h / 4h      │  4h only                       │
│  30x  D:SL=1%       │  21x, SL=2%                    │
│       S:SL=1.5%     │                                 │
│  D:트레일링 스탑    │  고정 SL/TP만                   │
│  S:고정 SL/TP       │                                 │
├─────────────────────┴────────────────────────────────┤
│  공유: 10 슬롯, 방향 다양성 max 2, Half-Kelly 사이징  │
└──────────────────────────────────────────────────────┘
```

**왜 두 축인가?** 하나의 전략은 반드시 "안 먹히는 시기"가 있다. VR Squeeze는 2023년에 PF=1.13(간신히 흑자)이었지만, 같은 기간 MA Cluster는 PF=1.31로 견고했다. 두 전략은 93.7% 서로 다른 시점에 신호가 발생해서, 하나가 쉬는 동안 다른 하나가 번다. 이것이 **비상관 다각화**의 핵심 가치다.

## 2. 핵심 개념: 변동성 스퀴즈란 무엇인가

### 2.1 왜 스퀴즈를 잡는가?

금융 시장의 변동성은 **군집(clustering)** 경향이 있다:
- 큰 움직임 뒤에는 큰 움직임이 온다
- 작은 움직임 뒤에는 작은 움직임이 온다
- 그리고 **작은 움직임이 오래 지속되면, 그 뒤에 큰 움직임이 터진다**

이 마지막 것이 스퀴즈다. 스프링을 세게 누르면 튀어오르듯, 가격이 좁은 범위에 오래 갇히면 그 에너지가 방향성 있는 급등/급락으로 풀린다.

스퀴즈를 잡는 건 추세추종(트렌드 팔로잉)과 다르다:
- **추세추종**: 이미 움직이고 있는 방향에 탑승 → 늦게 탈 수 있다
- **스퀴즈**: 아직 안 움직였지만 곧 움직일 것 → **초입에 진입** 가능

### 2.2 스퀴즈의 두 가지 형태

| 형태 | 감지 지표 | 비유 |
|:---|:---|:---|
| **VR Squeeze** | 단기 ATR / 장기 ATR 비율 급락 | 스프링이 눌린 상태 |
| **MA Cluster** | 4개 이동평균선이 한 점에 모임 | 시장 참여자들의 "합의" 상태 |

둘 다 "시장이 에너지를 축적하고 있다"는 동일한 현상을 다른 렌즈로 본다. 그래서 두 전략이 같은 시점에 동시에 발동하는 일이 드물다(6.3%만 겹침).

## 3. Axis 1: VR Squeeze — 스프링 압축 전략

### 3.1 VR이란 무엇인가

**VR (Volatility Ratio)** = ATR(8) / ATR(56)

- **ATR(n)**: Average True Range — 최근 n개 봉의 평균 변동폭 (%, 종가 대비)
- **ATR(8)**: 최근 8봉의 단기 변동성
- **ATR(56)**: 최근 56봉의 장기 변동성

VR이 높으면? 단기 변동성 > 장기 변동성 → 지금 시장이 활발히 움직이는 중.
VR이 낮으면? 단기 변동성 ≪ 장기 변동성 → 지금 시장이 비정상적으로 조용함 → **스퀴즈**.

```
VR = 1.0 → 단기와 장기 변동성이 같다 (보통 상태)
VR = 0.5 → 단기 변동성이 장기의 절반 → 매우 조용 → 스퀴즈!
VR = 0.3 → 극심한 압축 → 폭발 임박!
```

**왜 ATR% (퍼센트)인가?**  
ATR을 달러로 계산하면 BTC($60,000)와 DOGE($0.12) 비교가 불가능하다. 종가 대비 퍼센트로 변환하면 모든 코인에 같은 기준을 적용할 수 있다. 이것을 **스케일 불변(scale-invariant)**이라 한다.

**왜 8과 56인가?**  
- 8봉 ≈ 직전 2시간(15m) ~ 32시간(4h) 정도의 "지금" 변동성
- 56봉 ≈ 14시간(15m) ~ 224시간(4h) 정도의 "평소" 변동성
- 비율 = 56/8 = 7배 — 장기가 단기의 7배 기간이므로 스퀴즈 감지가 민감하면서도 안정적
- 이 파라미터는 6년(2020~2025) 데이터에서 반복 검증됨

### 3.2 VR 계산 코드 해설

```python
# signals.py (Numba JIT 컴파일 — 10,000회 이상 반복이므로 C 속도로 실행)

def _atr_pct(close, high, low, period):
    """ATR을 종가 대비 퍼센트로 계산"""
    # True Range = max(고-저, |고-전종|, |저-전종|) / 현재종가
    # → EMA(period)로 평활화
    
def compute_vr(close, high, low, short_period=8, long_period=56):
    """VR = ATR(8) / ATR(56)"""
    atr_s = _atr_pct(close, high, low, short_period)   # 단기
    atr_l = _atr_pct(close, high, low, long_period)    # 장기
    vr = atr_s / atr_l  # 비율!
    return vr
```

### 3.3 VR Squeeze의 두 가지 모드

#### D_mom8 (Directional — 방향성 진입)
- VR < **0.50** → "스퀴즈 감지됨"
- Momentum(8): 최근 8봉 동안의 가격 변화율 → **방향 결정**
  - 양수 → LONG (가격 상승 중에 스퀴즈 → 위로 터질 확률 높음)
  - 음수 → SHORT (가격 하락 중에 스퀴즈 → 아래로 터질 확률 높음)

```python
# momentum = close[-1] / close[-9] - 1
# 예: ETH가 8봉 전 3000 → 지금 3060이면 momentum = +2%
#     → LONG으로 진입
```

**왜 모멘텀으로 방향을 정하나?**  
스퀴즈는 "곧 터진다"는 건 알려주지만 "어느 방향으로"인지는 모른다. 모멘텀은 "지금 관성이 있는 방향"을 알려준다. 완벽하지 않지만(승률 25.9%), R:R이 3.75:1이라 적게 맞아도 돈을 번다.

#### S_d8 (Straddle — 양방향 동시 진입)
- VR < **0.55** 상태가 **4봉 연속** 이상 지속
- 방향을 모르겠으면? → **LONG + SHORT 동시 진입** (스트래들)
- 한쪽은 SL(-1.5%)에 걸리고, 다른 한쪽은 TP(+5%)를 노림
- R:R = 1.5:5 = 1:3.3 → 10번 중 3번만 맞아도 OK

```
스트래들 예시:
  ETH LONG  → SL=-1.5%, TP=+5%
  ETH SHORT → SL=-1.5%, TP=+5%
  
  가격이 위로 5% 가면: LONG +5%, SHORT -1.5% → 순이익 +3.5%
  가격이 아래 5% 가면: LONG -1.5%, SHORT +5% → 순이익 +3.5%
  횡보하면: 둘 다 -1.5% → 순손실 -3.0%
```

**왜 S_d8의 VR 임계값(0.55)이 D_mom8(0.50)보다 높은가?**  
스트래들은 양쪽 수수료를 내므로 조건이 너그러워야 더 자주 발생한다. 대신 4봉 연속 지속 조건으로 "거짓 스퀴즈"를 걸러낸다.

**신호 우선순위**: S_d8(스트래들) > D_mom8(방향). 같은 바에서 둘 다 조건 충족 시 스트래들이 이긴다.

### 3.4 F5 TBR Gate — 군중 역행 필터 (R46 검증, 현재 비활성)

**TBR (Taker Buy Ratio)** = 매수 체결량 / 전체 체결량. 1에 가까울수록 리테일 매수 군중이 몰린 상태.

TBR의 z-score가 극단적으로 높다는 것은 "이미 모두가 매수했다"는 의미다. 이때 롱을 진입하면 군중과 같은 방향 — 즉 시장이 이미 과매수 상태일 가능성이 높다.

```
F5 TBR Gate (D_mom8 전용, S_d8 스트래들 적용 안 함):
  
  z-score = (현재 TBR - 평균(192봉)) / std(192봉)

  LONG 진입 시도: z > +0.5 → 입장 거부 (리테일 FOMO 과열)
  SHORT 진입 시도: z < -0.5 → 입장 거부 (리테일 패닉 셀 과열)
  
  → 군중이 이미 한 방향에 쏠렸을 때 반대 방향을 노리는 게 아니라,
    단순히 "군중과 같은 방향인 신호는 거른다"
```

**R46 리서치 결과 (6yr, 46 symbols, lb=192, z>0.5):**
- PF: 1.306 → 1.348 (+0.042)
- WR: 42.6% → 46.4% (+3.8%p)
- N: -14.8% (진입 거절 증가)
- p-value: 0.029 (통계적 유의)

**왜 현재 비활성인가?**  
백테스트에서는 개선이 확인됐지만 라이브 실전 검증이 완료되지 않았다. `f5_tbr_enabled=True`로 바꾸면 활성화된다. **S_d8 스트래들에는 적용하지 않는다** — 방향 중립이라 TBR 방향성이 무의미하고, R46 리서치에서도 스트래들에 대한 검증을 실시하지 않았다.

```python
# config.py
f5_tbr_enabled: bool = False        # True로 바꾸면 라이브 활성화
f5_tbr_z_threshold: float = 0.5    # R46b 최적값
f5_tbr_z_window: int = 192         # lookback ~2일(15m 기준)
```

## 4. Axis 2: MA Cluster Squeeze — 합의 후 이탈 전략

### 4.1 MA Cluster란 무엇인가

4개의 SMA(Simple Moving Average)가 서로 가까이 모이는 현상:

```
SMA(20)  = 최근 20봉 평균 — "단기 추세"
SMA(50)  = 최근 50봉 평균 — "중기 추세"  
SMA(100) = 최근 100봉 평균 — "장기 추세"
SMA(200) = 최근 200봉 평균 — "초장기 추세"
```

4개 이평선이 좁은 범위(3% 이내)에 모이면:
- 단기·중기·장기·초장기 추세가 모두 **동일한 가격대**에 합의하고 있다
- 시장 참여자들이 "현재 가격이 적정하다"고 동의하는 상태
- 이 합의가 깨지면? → **새로운 추세의 시작**

### 4.2 클러스터 감지 조건

```python
# 매 4h 봉마다 체크:
spread = (max(SMA20, SMA50, SMA100, SMA200) 
        - min(SMA20, SMA50, SMA100, SMA200)) / close

# 조건 1: spread ≤ 3%  → 4개 이평선이 3% 이내로 수렴
# 조건 2: 이 상태가 8봉(32시간) 이상 지속
# 조건 3: 가격이 이평선 밴드를 이탈 (breakout)
# 조건 4: |momentum(8)| ≥ 1% → 충분한 방향성 확인
```

**왜 3%인가?**  
R44d 리서치에서 1%~5% 범위를 테스트. 3%가 "충분히 타이트하면서도 트레이드 수가 적당한" 균형점. 1%면 신호가 너무 적고, 5%면 노이즈가 너무 많다.

**왜 8봉(32시간)인가?**  
짧은 수렴(1~2봉)은 그냥 우연일 수 있다. 8봉이면 약 32시간 동안 합의가 유지된 것이므로 신뢰도가 높다.

### 4.3 필터들

#### 좀비 필터 (R45, max_duration=24)
```
24봉(96시간) 이상 클러스터가 지속되면 → 무시
```

**왜?** 이평선이 너무 오래 모여 있으면 이미 "구식 클러스터"다. 에너지가 서서히 빠져나간 상태이므로 터져도 크게 안 간다. 실전에서 이런 좀비 신호는 승률이 낮았다.

#### 모멘텀 필터 (R45, min_momentum=1%)
```
|momentum(8)| < 1% → 진입 거부
```

**왜?** 가격이 밴드를 이탈했어도 모멘텀이 약하면 "거짓 돌파"일 확률이 높다. 최소 1% 이상 움직여야 진짜 돌파로 인정.

#### 쿨다운 (한 클러스터 당 한 번)
```
한 클러스터 에피소드에서 신호는 딱 한 번만 발생
→ 클러스터 해소(spread > 3%)될 때까지 재진입 불가
```

**왜?** 같은 클러스터에서 여러 번 진입하면 실질적으로 같은 포지션을 중복으로 여는 것. 하나가 지면 전부 진다.

### 4.4 4h 전용인 이유

MA Cluster는 4h 차트에서만 동작한다.

- 15m에서 SMA(200) = 최근 200 × 15분 = 50시간 → 너무 짧다. "초장기 추세"가 아님.
- 4h에서 SMA(200) = 최근 200 × 4시간 = 800시간 ≈ 33일 → **의미 있는 장기 추세**.
- 더 높은 타임프레임(일봉, 주봉)은 신호가 너무 드물어 백테스트 데이터가 부족.

## 5. 진입 결정 과정 (Step-by-Step)

매 15분마다 (`on_bar`) 아래 과정이 50개 심볼에 대해 반복된다:

```
Step 1: 슬롯 체크
    └─ 현재 열린 포지션 < 10개? → No면 스캔 안 함

Step 2: 심볼별 15m 데이터 수신
    └─ close, high, low, volume 배열

Step 3: VR Squeeze 스캔 (우선순위 높음)
    ├── 4h VR 체크 (높은 TF 우선)
    │   └─ VR(8,56) < 0.50 → D_mom8 or S_d8?
    ├── 1h VR 체크 (15m을 4:1로 리샘플링)
    │   └─ VR(8,56) < 0.50?
    └── 15m VR 체크 (원본 데이터)
        └─ VR(8,56) < 0.50?
    
    D_mom8 진입 시 추가 게이트:
        └── F5 TBR z-score 체크 (f5_tbr_enabled=True일 때만)
            ├── LONG: z > +0.5 → 거부 (군중 과매수)
            └── SHORT: z < -0.5 → 거부 (군중 패닉셀)
    
Step 4: VR에서 신호 없으면 → MA Cluster 스캔
    └─ 4h 닫힌 봉 기준 SMA 클러스터 체크
        ├── spread ≤ 3%?
        ├── duration ≥ 8봉?
        ├── max_duration ≤ 24봉? (좀비 필터)
        ├── breakout? (가격이 밴드 밖?)
        └── |momentum| ≥ 1%?

Step 5: 신호 있으면 → 확신도 점수 계산 (CW-Tier)
    └─ E2 + C2 + B3 + A3 → 0~4점

Step 6: 포지션 사이징
    ├── per_slot_capital = balance / 10
    ├── leverage = 30x (VR) 또는 21x (MA)
    ├── CW 배율 적용 (0.5x ~ 2.5x)
    ├── SoftTight DD 스케일링 (드로다운 시 축소)
    └── notional = per_slot × leverage × CW × DD_scale

Step 7: 주문 실행
    ├── 레버리지 설정 (Binance API)
    ├── 지정가 추격 (LimitChaser)
    └── 서버 SL/TP 브라켓 설치
```

**왜 4h > 1h > 15m 우선순위인가?**  
높은 타임프레임의 신호가 더 신뢰도가 높다. 15m 스퀴즈는 2시간짜리 작은 압축일 수 있지만, 4h 스퀴즈는 며칠짜리 대형 압축이다. 대형 압축이 터지면 움직임도 크다.

**왜 VR이 MA Cluster보다 우선인가?**  
VR Squeeze가 더 오래 백테스트되었고(R31부터 누적 검증), 동시에 발동할 때 VR를 택하는 것이 역사적으로 더 나았다. %로 겹치는 비율이 6.3%에 불과하므로 실전에서 경합은 드물다.

## 6. 청산 메커니즘 (Exit)

### 6.1 VR Squeeze 청산 — 트레일링 스탑 (R43)

VR Squeeze의 핵심 아이디어: **승리 트레이드를 최대한 끌어가라.**

```
Phase 1: 고정 SL만 (-1%)
    └─ 아직 수익이 +2%에 도달하지 않음
    └─ 가격이 -1% 하락하면 → 손절 (stop_loss)

Phase 2: 트레일링 활성화 (수익 +2% 도달 후)
    └─ 고점 추적 시작
    └─ 고점 - 0.3% = 트레일 스탑 지점
    └─ 가격이 트레일 스탑에 닿으면 → 익절 (trailing_stop)
    
    예시:
      진입가: $100
      +2% 도달 ($102) → 트레일 활성화
      가격 $105까지 상승 → 트레일 스탑 = $105 × 0.997 = $104.685
      가격 $108까지 상승 → 트레일 스탑 = $108 × 0.997 = $107.676
      가격 $107로 하락 → $107 < $107.676 → 트레일 발동!
      실제 수익 ≈ +7% (고정 TP 5%보다 +2% 더 벌었다)

Phase 3: 하드 TP 천장 (+12%)
    └─ 어떤 경우든 +12% 도달하면 즉시 청산
    └─ 트레일링이 끝없이 욕심부리는 것을 방지

Phase 4: 시간 제한 (48시간)
    └─ 192봉(15m) 또는 12봉(4h) 보유 시 강제 청산
    └─ 스퀴즈가 안 터지고 횡보만 하는 경우 자금 묶임 방지
```

**왜 트레일링인가?** (R43 리서치 결과)
- 고정 TP=5%일 때: Average Win = +338bp
- 트레일링 활성화 후: Average Win = +357bp (+5.4% 개선)
- 손실 크기는 변화 없음 (Average Loss = -202bp)
- **순수하게 승리 트레이드의 이익만 늘렸다**

**왜 0.3% 트레일 거리인가?**  
- 너무 좁으면(0.1%): 정상적인 호가 변동에도 청산됨 (noise exit)
- 너무 넓으면(1%): 수익의 대부분을 반납하고 청산됨
- 0.3%: 노이즈는 무시하면서 진짜 반전에서 청산하는 균형점

### 6.2 MA Cluster 청산 — 단순 고정 (SL/TP)

```
SL = -2%  → 손절
TP = +8%  → 익절
Max Hold = 12봉 × 4h = 48시간 → 시간 제한
트레일링 스탑 없음
```

**왜 MA Cluster는 트레일링이 없나?**
MA Cluster의 브레이크아웃은 VR Squeeze와 패턴이 다르다. VR Squeeze는 "폭발"이라 고점을 쫓아가는 게 유리하지만, MA Cluster의 이탈은 더 점진적이다. R44d 백테스트에서 트레일링 추가가 성과를 개선하지 않았다.

### 6.3 스트래들 청산 — 심플

```
SL = -1.5%  → 손절
TP = +5%   → 익절
Max Hold = 48시간
트레일링 없음
```

스트래들은 양 방향으로 열리므로 한쪽은 거의 확실히 SL에 걸린다. 나머지 한쪽이 TP에 도달하면 순이익. 트레일링을 붙이면 반대쪽 손절과 시너지가 복잡해져서 단순함을 유지한다.

### 6.4 청산 우선순위 (같은 봉에서 여러 조건 충족 시)

```
1. 트레일링 스탑 (활성화된 경우)
2. 손절 (SL)
3. 익절 (TP)
4. 시간 제한 (Max Hold)
```

**왜 SL보다 트레일이 우선인가?**  
트레일이 활성화된 상태에서는 이미 수익 구간이다. 같은 봉에서 저점이 SL을 건드렸더라도 고점에서 트레일이 먼저 청산했을 수 있기 때문에 트레일을 먼저 체크한다.

## 7. 포지션 사이징과 레버리지 — Kelly Criterion

### 7.1 문제: 레버리지를 얼마나 써야 하나?

레버리지는 양날의 검이다:
- 너무 적으면 → 기회비용 (엣지가 있는데 안 쓴다)
- 너무 많으면 → **파산 위험** (연패 시 자금 고갈)

**Kelly Criterion**은 수학적으로 최적의 베팅 비율을 알려준다:

$$f^* = WR - \frac{1 - WR}{RR}$$

- $f^*$ = 전체 자금 중 한 번에 걸어야 할 비율
- $WR$ = 승률
- $RR$ = Risk:Reward 비율 (평균 이익 / 평균 손실)

### 7.2 QuantBox의 Kelly 계산

> **주의:** 아래 WR/RR은 **D_mom8 전용 분석치** (20260304 ef55e2e 리포트 기준, 방향성 단독).  
> S_d8 스트래들 포함 전체 VR 통계는 WR=43.4%, RR=1.67로 다르다.  
> 레버리지는 D_mom8 리스크 단위(SL=1%)로 도출됐으므로 아래 수치가 유효하다.

**VR Squeeze (D_mom8 기준):**
- WR = 25.9% (4번 중 1번 이김)
- RR = 3.75 (이기면 지는 것의 3.75배)
- $f^* = 0.259 - \frac{0.741}{3.75} = 0.259 - 0.198 = 0.061 = 6.1\%$

**MA Cluster:**
- WR = 38.6%
- RR = 2.05
- $f^* = 0.386 - \frac{0.614}{2.05} = 0.386 - 0.300 = 0.0865 = 8.65\%$

### 7.3 왜 Half-Kelly인가?

Full Kelly($f^*$)는 이론적 최적이지만 **현실에서는 위험하다**:

1. **파라미터 불확실성**: WR=25.9%는 6년 데이터의 추정값이지 확정값이 아님. 미래에 WR이 20%로 떨어질 수 있다.
2. **비정규 분포**: 시장은 가우시안이 아님. 테일 리스크가 Kelly 공식보다 큼.
3. **심리적 견딜 수 없음**: Full Kelly의 드로다운은 50%+가 일상적. 인간은 이걸 못 견딘다.

**Half Kelly = $f^*/2$**:
- 기대 수익의 약 75%를 유지하면서
- 드로다운은 절반 수준으로 감소
- 업계 실무 표준 (대부분의 헤지펀드가 Half Kelly 이하 사용)

### 7.4 레버리지 계산 공식

$$L = \frac{f^*/2 \times N}{SL}$$

- $L$ = 레버리지
- $f^*/2$ = Half-Kelly 비율
- $N$ = 슬롯 수 (10)
- $SL$ = 손절 비율

**VR Squeeze:**  
$$L = \frac{0.0307 \times 10}{0.01} = 30.7 \approx 30x$$

**MA Cluster:**  
$$L = \frac{0.0433 \times 10}{0.02} = 21.6 \approx 21x$$

### 7.5 Per-Trade Risk (실제로 얼마를 잃나?)

한 트레이드에서 SL이 발동하면:

$$\text{손실} = \frac{L \times SL}{N} = \frac{30 \times 0.01}{10} = 3.0\%\ (\text{VR})$$

$$\text{손실} = \frac{L \times SL}{N} = \frac{21 \times 0.02}{10} = 4.2\%\ (\text{MA})$$

**최악의 경우 (10개 슬롯 전부 동시 SL):**
- VR만: 10 × 3.0% = **30%**
- MA만: 10 × 4.2% = **42%**

이것이 50%를 넘지 않으므로 **단일 이벤트로는 파산하지 않는다**. 방향 다양성(max 2 같은 방향)이 10개 동시 SL 확률을 크게 낮춘다.

### 7.6 포지션 사이징 코드 흐름

```python
# positions.py — 매 진입 시 실행

balance = 1754.07                        # 현재 잔고
per_slot_capital = balance / 10          # $175.41 (슬롯당)
leverage = 30                            # VR Squeeze
notional = per_slot_capital * leverage   # $5,262 (실제 포지션 크기)

# SL=-1%면 최대 손실 = $5,262 × 1% = $52.62 = 잔고의 3.0%
```

## 8. 리스크 관리 장치들

### 8.1 SoftTight DD Scaling — 잃을수록 작게 베팅

```
세션 최고 잔고(HWM) 대비 드로다운 정도에 따라 자동으로 포지션 축소:

DD ≥ 2% → 포지션 크기 × 0.80 (80%)
DD ≥ 4% → 포지션 크기 × 0.60 (60%)
DD ≥ 6% → 포지션 크기 × 0.40 (40%)
```

**왜?** 연패는 지는 베팅의 크기가 줄어들어야 생존한다. "지고 있을 때 더 큰 판을 벌이는" 것은 파산의 지름길이다. Martingale(배팅 두 배 증가)이 아니라 **anti-Martingale**(잃으면 줄인다)이 올바른 리스크 관리다.

### 8.2 방향 다양성 (Direction Diversity)

```
같은 방향(LONG 또는 SHORT) 포지션은 최대 2개까지만
```

**왜?** 10개 포지션이 전부 LONG이면 BTC 급락 시 10개가 **동시에** SL에 걸린다. 방향을 섞으면 상호 헤지 효과가 발생하고, 최악의 시나리오(10개 동시 SL)를 구조적으로 불가능하게 만든다.

### 8.3 Max Drawdown Breaker — 비상 정지

```
세션 최고 잔고 대비 -10% 드로다운 → 전체 포지션 청산 + 봇 정지
```

**왜?** 시스템 오류, 시장 블랙스완, 논리 버그 등 예상 못한 사태에서 잠재적 손실을 10%로 강제 제한한다. 이 장치가 없으면 봇이 돌아가는 동안 잔고가 0에 접근할 수 있다.

### 8.4 서버사이드 SL/TP 브라켓

```
포지션 진입 즉시 → Binance 서버에 STOP 주문(SL) + TP 주문 등록
```

**왜?** 봇이 크래시하거나 인터넷이 끊져도 거래소 서버가 SL을 실행한다. 클라이언트 측 로직에만 의존하면 네트워크 장애 시 손절이 안 되는 재앙이 발생한다.

### 8.5 Limit Chaser — 수수료 절약

```
지정가 주문으로 체결 시도 → 1초마다 가격 추격 → 실패 시 시장가 폴백
```

**왜?** 바이낸스 선물 수수료: 시장가(Taker) 0.05% vs 지정가(Maker) 0.02%. 왕복 0.06% 차이인데 3,000번 트레이드면 수수료 차이만 180% 복리 차이가 난다.

## 9. 확신도 시스템 (CW-Tier Conviction Scoring)

### 9.1 직관

모든 스퀴즈가 같은 품질이 아니다. 더 많은 조건이 동시에 충족되면 신호가 더 신뢰할 만하다. 좋은 신호에 더 크게 베팅하고, 약한 신호에 작게 베팅한다.

### 9.2 4가지 조건

| 조건 | 코드 | 검사 내용 | 왜 중요한가 |
|:---|:---|:---|:---|
| **E2** | SMA 근접 | \|close - SMA(20)\| / SMA(20) < 0.5% | 가격이 평균 근처 = 진정한 스퀴즈. 평균에서 멀리 비정상적 가격이면 스퀴즈가 아니라 추세 연장일 수 있다 |
| **C2** | BTC 중립 | \|BTC momentum(8)\| < 1% | BTC가 급등/급락 중이면 알트코인은 BTC에 끌려다님. BTC가 조용해야 알트 자체의 스퀴즈가 의미 있다 |
| **B3** | 컨플루언스 | D_mom8과 S_d8이 동시 발동 | 두 독립 시그널이 같은 결론 → 신뢰도 상승. "두 의사가 같은 진단" |
| **A3** | 퀄리티+ | D: VR < 0.35 (깊은 압축) / S: 지속 ≥ 16봉 | "보통 스퀴즈"보다 더 극심한 압축은 폭발 에너지도 더 크다 |

### 9.3 CW-Tier 배율

| Score | 조건 수 | 배율 | 의미 |
|:---:|:---:|:---:|:---|
| 0 | 0개 | **0.5x** | 최소 확신 — 스퀴즈는 있지만 보조 근거 없음 |
| 1 | 1개 | **1.0x** | 기본 (baseline) |
| 2 | 2개 | **1.5x** | 보통 확신 |
| 3 | 3개 | **2.0x** | 높은 확신 |
| 4 | 4개 | **2.5x** | 최고 확신 — 모든 조건 충족 → 최대 베팅 |

```
예시:
  balance = $1,754, slot = $175.40, leverage = 30x
  
  Score 0: notional = $175.40 × 30 × 0.5 = $2,631
  Score 2: notional = $175.40 × 30 × 1.5 = $7,893  (3배 차이!)
  Score 4: notional = $175.40 × 30 × 2.5 = $13,155
```

**주의:** CW-Tier는 VR Squeeze에만 적용된다. MA Cluster에는 적용되지 않는다 (별도 검증 미실시).

## 10. 멀티 타임프레임 (MTF)

### 10.1 왜 여러 타임프레임을 보나?

같은 시장을 다른 해상도로 보면 다른 것이 보인다:

```
15분봉: "지금 2시간 동안 조용해" → 작은 스퀴즈
 1시간봉: "지금 하루 동안 조용해" → 중간 스퀴즈  
 4시간봉: "지금 며칠째 조용해"   → 큰 스퀴즈 ← 이게 진짜
```

### 10.2 리샘플링

15m 데이터만 다운로드하고, 1h와 4h는 **리샘플링**으로 만든다:

```python
# 15m 4개 봉 → 1h 1개 봉
1h_close = 15m_close[3]      # 마지막 15m의 종가
1h_high  = max(15m_high[0:4]) # 4개 중 최고가
1h_low   = min(15m_low[0:4])  # 4개 중 최저가
1h_vol   = sum(15m_vol[0:4])  # 거래량 합계
```

**중요: 나머지(remainder) 봉은 잘라낸다.** 15m 봉이 10개면 1h 봉은 2개(8개 사용, 2개 버림). 진행 중인 봉을 포함하면 미래 데이터를 참조하게 된다 (→ 룩어헤드 바이어스).

### 10.3 VR Squeeze의 MTF 우선순위

```
4h VR < 0.50? → 4h 조건 우선 사용 (가장 큰 스퀴즈)
               아니면 ↓
1h VR < 0.50? → 1h 조건 사용
               아니면 ↓
15m VR < 0.50? → 15m 조건 사용
               아니면 ↓
                → 신호 없음
```

4h가 가장 먼저 체크되는 이유: 더 높은 타임프레임의 스퀴즈가 더 큰 움직임을 만들기 때문이다.

## 11. 룩어헤드 바이어스 방지

### 11.1 무엇이 룩어헤드인가?

백테스트에서 "미래 데이터"를 사용하는 실수. 예를 들어:

```python
# 잘못된 코드 (LOOKAHEAD!)
```

### 11.2 QuantBox의 룩어헤드 방지 설계

1. **완성된 봉만 사용**: `on_bar`는 15m 봉이 **닫힌 후**에 호출됨
2. **리샘플링 시 나머지 절단**: `n_out = n // ratio` — 나머지(개발 중 봉) 제거
3. **신호는 마지막 봉만 체크**: `sig[-1]`만 확인. 과거 봉의 신호는 참고용일 뿐 진입하지 않음
4. **교차 TF 참조는 완성된 바만**: 4h 데이터는 거래소에서 완성된 4h 봉을 직접 가져옴
5. **Numba 함수의 인덱스 설계**: 모든 계산에서 `i-1`까지만 참조

### 12.2 왜 PF와 EV가 "불변 엣지"인가?

$$PF = \frac{\text{총 이익}}{\text{총 손실}}$$

PF는 트레이드 레벨의 비율이다. 레버리지가 2배면 이익과 손실이 둘 다 2배가 되므로 비율은 같다. 데이터 기간이 달라져도 전략의 "실력"을 반영하므로, 버전 간 비교에 가장 신뢰할 수 있는 지표다.

반면 **연간수익률**은 복리 기간(4.73년 vs 6년)과 레버리지 모델(1x vs L/N=3.0)에 따라 극적으로 달라지므로 나란히 비교가 위험하다.

### 12.3 수익률 복리의 함정

같은 PF=1.31, 같은 EV=+24bp라도:

```
4.73년 × 1x compound → +281%
6.0년  × 1x compound → 약 +500%  (기간 1.27배인데 수익 1.8배!)

이유: 복리의 지수적 성질. (1.001)^N은 N이 커지면 급격히 커진다.
```

**교훈:** 수익률을 인용할 때 반드시 (1) 데이터 기간, (2) 레버리지 모델, (3) 복리 방식을 같이 명시해야 한다.

## 13. 실거래 안전장치

### 13.1 서버 SL/TP 브라켓

포지션 진입 즉시 거래소 서버에 두 개의 조건부 주문을 등록:

```
STOP 주문 (SL): 가격이 entry × (1 - SL%) 도달 시 자동 청산
TP 주문: 가격이 entry × (1 + TP%) 도달 시 자동 청산
```

**존재 이유:** 봇 프로세스 사망, 서버 다운, 네트워크 장애 등 클라이언트 측 모든 장애 상황에서도 손절이 보장된다.

### 13.2 State Persistence (크래시 복구)

```
매 포지션 변경 시 → data/state/scalper_state.json에 원자적(atomic) 기록
봇 재시작 시 → JSON에서 포지션 복원 + 거래소 API 대조
```

**존재 이유:** 봇이 죽었다 살아나도 "내가 어떤 포지션을 가지고 있었는지" 잊지 않는다.

### 13.3 레버리지 검증

```python
resp = client.futures_change_leverage(symbol=symbol, leverage=30)
actual = resp['leverage']
if actual != 30:
    logger.error("레버리지 불일치 — 주문 취소!")
    return None  # 진입 거부
```

**존재 이유:** 레버리지 설정이 실패한 채 주문이 나가면, 의도하지 않은 크기의 포지션이 열린다. Incident #1에서 실제 발생.

### 13.4 Reduce-Only 안전 규칙

```
포지션 축소/청산 주문에서는 절대로:
  × leverage 변경 API 호출 금지
  × margin mode 변경 금지
```

**존재 이유:** Incident #1. reduce_only 주문에서 leverage 변경을 시도하면 API -2028 에러가 나고 TP1 주문이 실패한다.

### 13.5 알고 주문 상태 완전 체크 (Incident #4 수정 반영)

바이낸스 조건부 주문(Algo)의 실제 상태 전이:

```
WORKING → TRIGGERED → FINISHED
          (순간적)    (최종 완료)
```

`_check_order_filled()`는 `TRIGGERED`와 `FINISHED` 모두를 "체결"로 처리한다.

```python
# 올바른 체크 (수정 후)
if status in ('TRIGGERED', 'FINISHED'):
    return True  # 체결 완료

# 잘못된 체크 (수정 전)
if status == 'TRIGGERED':  # FINISHED를 놓침!
    return True
```

**존재 이유:** Incident #4. 'FINISHED' 누락 시 모든 서버 SL/TP 체결을 감지 못해 `_reconcile_positions()`의 고스트 감지에만 의존하게 된다. 고스트 감지 시 반대편 알고 주문(대응 SL 또는 TP)이 미취소돼 다음 포지션에 간섭한다.

## 14. 자주 하는 실수와 교훈

### Incident #1: Reduce-Only Leverage Crash

**무슨 일이?** 부분 익절 시 `futures_change_leverage()` 호출 → API -2028 → TP1 실패 → 수익 확정 못 함.  
**교훈:** 포지션을 줄이는 주문은 레버리지를 건드리지 마라.

### Incident #2: 4h MTF Lookahead Bias

**무슨 일이?** 리샘플링 시 `i // ratio`가 아직 닫히지 않은 4h 봉의 종가를 참조 → 백테스트 WR 83%, 라이브 WR 36%.  
**교훈:** `j = (i // ratio) - 1`로 완성된 봉만 참조. "이 바가 진행 중일 때 이 값을 알 수 있는가?" 항상 자문.

### Incident #3: Dynamic Capital 50% Cap

**무슨 일이?** 포지션 0개일 때 `balance / max(1, 0+1) = balance` → 50% cap → $991 → 12x = $11,888 → SL -2% = **$228 손실** (잔고의 11.5%).  
**교훈:** 포지션 사이징은 반드시 `balance / max_concurrent` 하드캡. n_active=0인 상태에서 테스트 필수.

### Incident #4: Algo Order FINISHED Status

**무슨 일이?** `_check_order_filled()`가 `algoStatus == 'TRIGGERED'`만 검사 → 바이낸스 최종 상태는 `'FINISHED'` → 모든 서버 SL/TP 체결을 감지 못함 → `_reconcile_positions()` 고스트 감지에 의존 → 반대편 알고 주문(SL 또는 TP) 미취소 → 고아 주문 잔류.  
**교훈:** 바이낸스 알고 주문 상태는 `TRIGGERED`와 `FINISHED` 모두 체결로 처리. 서버 체결 감지 로그는 `INFO` 레벨. 고스트 감지 시 반드시 반대편 알고 주문도 취소.

### 공통 교훈

1. **돈이 오가는 코드는 양쪽 경로 모두 테스트하라** (진입 + 청산)
2. **다른 전략에서 복사한 공식은 슬롯 수 차이로 의미가 바뀐다** (2슬롯 ≠ 10슬롯)
3. **백테스트 WR이 라이브의 2배 이상이면 룩어헤드를 의심하라**

## 15. 용어 사전

| 용어 | 설명 |
|:---|:---|
| **ATR** | Average True Range. 일정 기간의 평균 변동폭. 시장의 "심박수" |
| **VR** | Volatility Ratio = ATR(단기) / ATR(장기). 1보다 작으면 압축 상태 |
| **SMA** | Simple Moving Average. 단순 이동평균 |
| **Squeeze** | 변동성 압축 상태. 가격이 좁은 범위에 갇힘 |
| **Breakout** | 가격이 눌려있던 범위를 벗어나는 것 |
| **Momentum** | 일정 기간의 수익률. `close / close[-N] - 1` |
| **SL** | Stop Loss. 손절 가격/비율 |
| **TP** | Take Profit. 익절 가격/비율 |
| **PF** | Profit Factor = 총이익 / 총손실. 1 이상이면 흑자 |
| **WR** | Win Rate. 승률 |
| **R:R** | Risk:Reward. 평균 이익 / 평균 손실 |
| **EV** | Expected Value. 한 트레이드 당 기대 수익 (bp 단위) |
| **bp** | Basis Point = 0.01%. 100bp = 1% |
| **Calmar** | 연수익률 / 최대 드로다운. 위험 대비 수익 효율 |
| **DD** | Drawdown. 최고점 대비 하락폭 |
| **HWM** | High Water Mark. 세션 최고 잔고 |
| **MFE** | Maximum Favorable Excursion. 포지션 보유 중 도달한 최대 이익 |
| **MAE** | Maximum Adverse Excursion. 포지션 보유 중 도달한 최대 손실 |
| **Kelly** | Kelly Criterion. 수학적으로 최적의 베팅 비율을 계산하는 공식 |
| **Half-Kelly** | Full Kelly의 절반. 업계 표준 보수적 사이징 |
| **L/N** | Leverage / N(슬롯 수). 슬롯당 유효 레버리지 |
| **Numba** | Python JIT 컴파일러. 반복 연산을 C 속도로 실행 |
| **Hedge Mode** | 바이낸스의 양방향 포지션 모드. LONG과 SHORT 동시 보유 가능 |
| **Straddle** | 같은 자산에 LONG + SHORT 동시 진입. 방향 모를 때 사용 |
| **Cooldown** | 같은 신호 반복 방지 위한 대기 시간 |
| **Zombie signal** | 너무 오래된 클러스터에서 나온 무의미한 신호 |
| **Lookahead bias** | 백테스트에서 미래 데이터를 참조하는 오류 |
| **Parity** | 백테스트 로직 = 실거래 로직. 둘이 다르면 무의미 |
| **Bootstrap** | 데이터를 무작위 서브샘플링하여 통계적 신뢰구간 계산 |
| **Compound** | 복리. 수익을 재투자하여 지수적 성장 |
